Hash Table & Caching: The Crash Course

Goal: Map a potentially infinite key space (Strings, Objects) to a finite array index using the formula: Index = hash(Key) % Array_Size.

I. The Core Mechanism

You cannot store keys "as is" because the address space would be too vast. Hashing "compresses" the key into a usable integer.

  • Average Case: O(1) (Constant time).
  • Worst Case: O(n) (All keys collide into one bucket).

II. Collision Handling Strategies

When hash(A) % N == hash(B) % N, you need a strategy.

Feature Separate Chaining (Java) Open Addressing (Python)
Concept "Let them pile up." The bucket holds a pointer to a Linked List. Colliding items hang off the bucket. "Find another spot." If the bucket is full, probe (jump) to the next available slot in the main array.
Probing None. Traverse the list at that specific index. Linear: +1 (Fastest, causes clustering).
Quadratic: +1, +4, +9 (Less clustering).
Double Hashing: Uses 2nd hash for step size.
Deletion Easy. Remove node from list. Hard. Requires Tombstones. You cannot leave a null or you break the search chain.
Load Factor Can tolerate high Load Factor (0.75+). Needs low Load Factor (< 0.66) to keep the array sparse.

III. Advanced Internals

1. Java HashMap

  • Optimization (Java 8+): If a collision chain grows beyond 8 nodes, it converts the Linked List into a Red-Black Tree. This improves worst-case lookup from O(n) to O(log n).
  • Concurrency (ConcurrentHashMap):
    • Reads: Lock-free (volatile).
    • Writes: Uses CAS (Compare-and-Swap) for empty slots. If occupied, it locks only that specific bucket (Fine-grained locking).

2. Python Dict

  • Memory Optimization: Uses "Compact Dict" (Split arrays).
    • Indices Array: Dense, small integers pointing to data.
    • Entries Array: Stores actual data in insertion order.
  • Probing: Uses a pseudo-random probing sequence based on the hash to avoid clustering.

IV. Probabilistic Structures

Trade-off: Save massive space by accepting a small probability of error.

1. Bloom Filters

A space-efficient probabilistic data structure to test whether an element is a member of a set.

  • Returns: "Possibly in set" or "Definitely not in set".
  • False Positives: Possible (collisions in bit array).
  • False Negatives: Impossible.
  • Mechanism: Uses k different hash functions to set bits in an m-bit array.
  • Use Case: Database checks (avoid disk read if key doesn't exist), Weak Password checks.

2. Cuckoo Hashing

A scheme that resolves collisions by using two hash functions and two tables.

  • Lookup: O(1) worst-case. It's in position h1(x) or h2(x). No searching chains.
  • Insertion: If both spots are full, kick out the existing item to its alternative spot ("Cuckoo" behavior). This can cascade.
  • Cycle: If a cycle of kicking occurs, re-hash everything.

V. Critical Interview Concepts

1. The Mutable Key Trap

Rule: Keys must be Immutable (e.g., String, Integer).

The Bug: If you modify a key after putting it in the map, its hash code changes. The map looks for it in the "new" bucket index, but the entry is sitting in the "old" bucket. The data is lost in memory ("Ghost Entry").

2. Resizing & Amortized Complexity

When Size > Capacity * Load_Factor, the map creates a double-sized array and re-hashes every single item.

Cost: O(n). This makes Hash Map insertion "Amortized O(1)" (fast usually, slow occasionally).

3. Distributed Systems: Consistent Hashing

Problem: In a distributed cache (e.g., Redis cluster), if one server dies, hash % N changes for everyone. 100% of keys move.

Solution: Map servers and keys to a 360° Ring. Keys move clockwise to the nearest server.

Benefit: If a server dies, only 1/N of keys move. The rest stay put.

VI. The LRU Cache (System Design)

Goal: A cache that deletes the "Least Recently Used" item when full.

HashMap
Maps Key → Node Address (Speed: O(1))
Doubly Linked List
Maintains Order. Head = Most Recent. Tail = Least Recent.

Why Doubly Linked? So you can delete a node from the middle in O(1) without traversing the list to find the "previous" pointer.
