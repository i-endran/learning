Reductions: The Art of Translation

How do we know a problem is hard? By showing that it's at least as hard as another problem we already know is hard. This technique is called "Reduction".

What is a Reduction?

Imagine you want to solve Problem A. You don't know how to solve it directly, but you have a magic black box (algorithm) that solves Problem B. If you can transform your input for Problem A into an input for Problem B, use the box, and then transform the answer back... you've just "Reduced A to B".

Problem A Input → Convert → Problem B Input → Solver for B → Answer

Notation: A ≤P B means "A reduces to B in polynomial time".

Why is this useful?

To prove hardness:

If we know A is Hard, and we show that A ≤P B, then B must also be Hard.
(Because if B were easy, we could use the reduction to solve A easily, which is a contradiction.)

To find solutions:

If we know B is Easy, and A ≤P B, then A is Easy.
