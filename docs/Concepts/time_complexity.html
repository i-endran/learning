Time Complexity & Big O

Understanding how algorithms scale efficiently is at the heart of computer science. We use "Big O" notation to classify algorithms by how their running time or space requirements grow as the input size grows.

Common Complexity Classes

From fastest to slowest growth rates.

Notation Name Example
O(1) Constant Time Accessing an array element by index.
O(log n) Logarithmic Time Binary Search.
O(n) Linear Time Simple iteration (for loop).
O(n log n) Linearithmic Time Efficient sorting (Merge Sort, Quick Sort).
O(n^2) Quadratic Time Nested loops (Bubble Sort).
O(2^n) Exponential Time Recursive Fibonacci (naive).
O(n!) Factorial Time Traveling Salesperson (Brute Force).

Why Polynomial Matters (The "P" in P vs NP)

In complexity theory, we draw a major line in the sand between Polynomial Time (O(nk) for any constant k) and Exponential Time.

Algorithms that run in polynomial time are generally considered "efficient" or "feasible" for large inputs. Algorithms that take exponential time become impractical very quickly as input size increases.
